# 17. Розробка, маючи лише Android

Редакція 0.7 від 15.11.2026. Умова власника: є лише Android. Це план робочого процесу; віддалений Unity Editor, активація та нова APK-збірка ще не налаштовані.

## 1. Що реально можливо

Власний комп'ютер не обов'язковий, якщо Unity Editor і збірка доступні на зовнішній підтримуваній машині або в сервісі. Телефон тоді є робочим інтерфейсом і пристроєм перевірки гри.

Unity Editor офіційно підтримується на Windows, macOS і Linux; Android у вимогах — платформа запуску гри, а не нативного редактора. Termux не перетворює Android на підтримувану систему для Unity Editor. Джерело: [вимоги Unity 6.3](https://docs.unity3d.com/6000.3/Documentation/Manual/system-requirements.html).

| Робота | З телефона | Що потребує зовнішнього середовища |
| --- | --- | --- |
| Дизайн, баланс, описи, переклади | Обговорення, правки Markdown/JSON, перевірка змін у GitHub | Нічого для самих текстів |
| Код і версії | C#, конфігурації та Editor-скрипти через GitHub/Codex; Termux для локального Git за потреби | Імпорт Unity, компіляція та перевірка API |
| Перша сцена й примітивні моделі | Підготовка коду генерації героя, ворога, карти й UI | Виконання коду в Unity Editor, створення сцен/префабів |
| Детальні моделі, матеріали, rig та анімації | Референси, специфікації, перегляд результатів | Практичний маршрут для візуального редагування — віддалене робоче місце з потрібними редакторами |
| APK | Запуск налаштованого процесу, завантаження результату, встановлення | Unity Editor із Android build support, потрібна активація та сама збірка |
| Ігрове тестування | Рух, мультитач, здібності, збереження, фон/повернення, нагрів, відеозвіти | Виправлення й повторна збірка; профілювання за потреби |

Один телефон перевіряє поведінку лише на своїй конфігурації. Цільову продуктивність для інших пристроїв встановлюємо після окремих вимірів.

## 2. Варіанти зовнішньої роботи

| Маршрут | Для чого підходить | Передумови й поточний статус |
| --- | --- | --- |
| GitHub Actions + GameCI | Автоматичний імпорт проєкту й Android-збірки з репозиторію | Потрібні Unity-проєкт, сумісний зафіксований Editor, активація й налаштований workflow. Для нової гри цього ще немає |
| Unity Build Automation | Збірки з Git-репозиторію, завантаження результату на телефон | Потрібні Unity-акаунт, підключення приватного репозиторію та Android build configuration. Послуга ще не підключена |
| Віддалений комп'ютер | Візуальна робота зі сценами, імпортом, rig, анімаціями та профайлером | Потрібні доступна машина, підтримувана ОС, встановлений Unity і віддалене керування з Android. Доступ не підтверджено |

Перший робочий напрям — код у GitHub, прості сцени через Editor-скрипти та зовнішня APK-збірка. Це дозволяє перевірити механіку до великого художнього виробництва. Для точного ручного компонування згодом знадобиться практичний доступ до редактора, наприклад через віддалений екран.

Unity підтримує запуск власних Editor-методів у batch mode. Це спосіб автоматизувати підготовку сцени й build на зовнішній машині, а не запуск Unity Editor на Android. Джерело: [аргументи командного рядка Unity 6.3](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html).

## 3. Активація й доступ

GameCI вимагає активації Unity; самі C#-файли й GitHub workflow не дають готову ліцензовану збірку. Поточний маршрут GameCI для Personal починається з активації через Unity Hub на підтримуваній настільній системі. Не обіцяємо, що цей етап уже можна пройти в наявному Android-середовищі. Джерела: [GameCI activation](https://game.ci/docs/github/activation/), [Unity license activation methods](https://docs.unity.com/en-us/engine/6000.6/manual/get-started/install-and-upgrade/licenses-and-activation/license-activation-methods).

Для Unity Build Automation окремо перевіряються доступний план, квота й підтримка потрібної версії. У Unity описаний безкоштовний обсяг використання; він обмежений. Умови конкретного акаунта ще не перевірено; платні ресурси й передплати не створювалися. Джерела: [Unity pricing updates](https://unity.com/products/pricing-updates), [налаштування build](https://docs.unity.com/en-us/build-automation/basic-build-configuration/overview).

Доступ до приватного репозиторію налаштовується в обраному сервісі; для CI облікові дані зберігаються у відповідних захищених налаштуваннях. Паролі, ліцензійні файли, токени й ключі підпису не додаються в документацію або Git. Для початку достатньо внутрішнього debug APK; публікація — окремий етап.

## 5. Перший результат і критерії

| Етап | Результат | Як приймаємо |
| --- | --- | --- |
| M0: збірка | Зафіксовані Editor/пакети, імпорт проєкту, перший debug APK | Є успішний лог збірки; APK встановлюється й запускається на телефоні |
| M1: керування | Альбомний екран, м'яка камера, герой, джойстик, автоатака й один ворог | Одночасний рух і атака, робота обох орієнтацій, повернення з фону без завислого вводу |
| M2: три функції | AB-PULL, AB-MOVE, AB-DAMAGE та окремі праві кнопки/КД | Кожна функція має свій результат; валідна ціль і доступність видимі; невалідний запуск не обходить перевірки |
| M3: цикл світу | Невеликий зв'язний фрагмент різної небезпеки, сейв-зона, валютне відкриття, смерть і збереження | Можна перейти туди й назад; смерть переносить у сейв-зону; погоджений штраф списується один раз; прогрес читається після перезапуску |

Частка штрафу, конкретна сейв-зона після смерті й доля мутацій залишаються в B-01. Поки вони не узгоджені, реалізаційні числа повинні бути явно позначеними тестовими параметрами. Значення 10% не стало погодженим правилом.

Перший прототип використовує прості форми та мінімальний контент. Це обсяг першої перевірки, а не заміна погодженого повністю відкритого світу окремими рівнями. Великий світ, деталізацію моделі й фінальні анімації плануємо за результатами керованості та вимірів.

## 6. Цикл роботи з телефона

1. Узгоджуємо пов'язаний блок механік і записуємо рішення в GitHub.
2. Готуємо код, дані, сцену й завдання збірки.
3. Зовнішній Editor імпортує проєкт; процес виконує перевірки й збирає APK.
4. На Android встановлюємо APK і перевіряємо конкретний сценарій; записуємо версію, кроки й результат.
5. Виправляємо знайдене та повторюємо збірку. Успішна компіляція не замінює запуск на телефоні.

До готовності M0 можна повноцінно вести дизайн, писати код і конфігурації. Позначати їх як перевірену Unity-гру можна лише після виконання відповідних перевірок.
