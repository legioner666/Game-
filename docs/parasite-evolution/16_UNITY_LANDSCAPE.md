# 16. Unity, горизонтальний екран і пакет керування

Редакція 0.7 від 15.11.2026. Пов'язані рішення: D-02, D-03, D-04, D-15, D-21, D-22.

## 1. Вихідні рішення й рекомендація

Після питання про Unity та горизонтальний екран власник погодив запропонований блок. **Погоджена база нової гри: Unity 6.3 LTS, C#, URP та обидві альбомні орієнтації.** Конкретний Editor patch і версії пакетів ще не вибрані.

Горизонтальна орієнтація замінює початковий портретний бриф. Точний Unity Editor patch і версії пакетів фіксуємо при створенні проєкту. Згаданий у старому стані репозиторію Godot 4.4.1 належить Crown Rush та історії первісного плану.

Офіційна сторінка підтримки вказує для Unity 6.3 LTS підтримку до грудня 2027; це підстава вибрати підтримувану гілку, а не прогноз продуктивності нашої гри: [джерело](https://unity.com/releases/unity-6/support). URP охоплює мобільні платформи: [вступ Unity](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/urp-introduction.html).

## 2. Пакет B-02: технічна база й керування

Погодження стосується показаного власнику блоку. Технічні деталі, яких у ньому не було, зберігають окремий статус.

| Пункт | Параметр | Статус |
| --- | --- | --- |
| B02-01 | Unity 6.3 LTS + C# + URP | Погоджено; точний patch і пакети відкриті |
| B02-02 | Горизонтальна орієнтація; підтримати обидва альбомні боки | Погоджено; налаштування автоповороту перевіряються на пристрої |
| B02-03 | Камера зверху під кутом, м'яке слідування | Погоджено; проєкція, кут і ручне обертання ще відкриті |
| B02-04 | Рух джойстиком зліва з підтримкою одночасних дотиків справа | Лівий джойстик погоджено; мультитач — вимога реалізації |
| B02-05 | Автоматична базова атака під час руху; ручне рішення лишається за здібностями | Погоджено; правила вибору цілі ще налаштовуються |
| B02-06 | До трьох кнопок відкритих функцій справа, окремі cooldown; недоступні не запускаються | Кнопки й окремі КД погоджено; числа та прицілювання відкриті |
| B02-07 | Здоров'я й прогрес угорі, вільний бойовий центр; адаптивна розкладка та safe area | Основну розкладку погоджено; адаптація — критерій перевірки |
| B02-08 | Android як робочий інтерфейс; Editor і збірка на зовнішній машині/сервісі | Власник має лише Android; середовище ще не налаштоване, план — розділ 17 |

Пакет B-01 про смерть і сейв-зони зберігається окремо. Власник може змінювати кілька пов'язаних рядків одним повідомленням і переходити між блоками без втрати вже зафіксованих рішень.

## 3. Початкова структура Unity-проєкту

Пропонується корінь `parasite-evolution/` з такими каталогами:

| Шлях | Вміст |
| --- | --- |
| `Assets/_Game/Scenes/` | Bootstrap, постійна сцена, блоки світу та тестова кімната |
| `Assets/_Game/Prefabs/` | Герой, вороги, відростки, сейв-зони, UI й модулі середовища |
| `Assets/_Game/Scripts/` | C#-логіка бою, світу, прогресу, смерті та інтерфейсу |
| `Assets/_Game/Data/` | Незмінні визначення й баланс; робочий формат — ScriptableObject |
| `Assets/_Game/Art/` | FBX, матеріали, текстури й анімації |
| `Assets/_Game/Audio/` | Ефекти, фон і музика |
| `Packages/` | Зафіксований склад пакетів та lock-файл |
| `ProjectSettings/` | Версія редактора, Android, input, renderer та інші параметри |

Це план; Unity-проєкт і APK у цій документаційній редакції ще не створені. Майбутні `.meta` зберігаються разом з асетами, щоб не втрачати посилання. Кеш редактора не є вихідним кодом.

## 4. Рух, щупальця й навігація

Для першої перевірки пропонуються `CharacterController` для героя, `NavMeshAgent` для звичайної навігації ворогів і окреме кероване переміщення при захопленні. Примусова тяга й агент не повинні одночасно керувати тією самою позицією. Джерела: [CharacterController](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/CharacterController.html), [NavMeshAgent](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AI.NavMeshAgent.html).

Корпус і базові пози — через Animator; відростки — через власну керовану C#-логіку поверх скелета. Точний rig і додаткові animation-пакети перевіряємо на одному імпортованому асеті. Сам вибір Unity не робить гак або відкритий світ готовими компонентами.

## 5. Карта й підвантаження

Пропонується постійна сцена з героєм і сервісами та підвантажувані блоки через additive scenes. Unity документує додавання сцени без вивантаження вже завантажених: [LoadSceneMode.Additive](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/SceneManagement.LoadSceneMode.Additive.html).

Планувальник блоків, їх збереження, навігаційні стики та утримання активного гака реалізуються нашою логікою. Зони складності не зобов'язані збігатися зі сценами. Addressables та інші додаткові пакети обираємо лише за конкретною потребою, не вважаємо вже встановленими.

## 6. Альбомний Android-інтерфейс

Пропозиція налаштування: AutoRotation із дозволеними Landscape Left/Right і вимкненими портретними режимами. На повороті скидаються старі дотики, адаптується safe area й перевіряється розкладка. Джерела: [ScreenOrientation](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/ScreenOrientation.html), [Screen.safeArea](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Screen-safeArea.html).

Герой лишається видимим між зонами великих пальців. Зліва — рух; справа — до трьох кнопок відкритих функцій з окремими КД; угорі — здоров'я й прогрес. Позиції валюти, карти, паузи та короткої цілі уточнюються без перекриття бойового центру.

## 7. Асети, запис даних і збірка

Для нового пайплайна пропонується FBX для моделей/анімацій і окремі текстури. Офіційна документація рекомендує FBX як виробничий обмінний формат: [формати моделей](https://docs.unity3d.com/6000.3/Documentation/Manual/3D-formats.html). Вихідні художні файли зберігаються окремо від імпортованого набору.

Робочі runtime-стани й транзакції смерті/валюти відділені від ScriptableObject-конфігурацій. Для локального запису використовується придатний для застосунку шлях; API: [Application.persistentDataPath](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Application-persistentDataPath.html). JSON-контракт і його виконавець перевіряються окремо.

Редактор має настільні вимоги Windows/macOS/Linux: [системні вимоги](https://docs.unity3d.com/6000.3/Documentation/Manual/system-requirements.html). Телефон — ціль для встановлення й тесту Android-збірок. Конкретна build-машина та CI ще не налаштовані; старий Godot workflow не є Unity-збіркою.

Власник працює лише з Android. Код і GitHub ведемо з телефона; перший прототип можна готувати зі створенням сцени C#-скриптами, а запускати Editor і збирати APK у зовнішньому середовищі. Ліцензія, доступ до збірки та її результат ще не перевірені. Детальний маршрут — [розділ 17](17_ANDROID_ONLY_WORKFLOW.md).

## 8. Перший практичний результат

Коли переходимо до реалізації: зафіксований Unity patch, простий URP-проєкт, альбомна тестова сцена, керований герой, один ворог, один робочий контакт і debug APK. Потім — три функції, смерть із поверненням у сейв-зону та зв'язний фрагмент відкритого світу. Це план наступної роботи, а не виконана перевірка.
